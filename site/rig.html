Connecting your radio

On The Dial does not talk to radios itself. It asks a small helper program, and that helper knows hundreds of radios.

The idea in one picture

  ┌──────────────┐   USB / serial / LAN   ┌──────────────┐   TCP port 4532   ┌──────────────┐
  │  your radio  │ ◄────────────────────► │   rigctld    │ ◄───────────────► │  On The Dial │
  └──────────────┘                        │  (Hamlib)    │ ◄───────────────► │  QLog, WSJT-X│
                                          └──────────────┘                   │  fldigi, ...  │
                                                                             └──────────────┘

rigctld is part of Hamlib, the free library that knows how to speak to Icom, Yaesu, Kenwood, Elecraft, FlexRadio and many more. It runs in the background, holds the connection to the radio, and offers it to any number of programs on network port 4532. On The Dial only ever asks it "what frequency and mode is the VFO on?" and, when you double-click a station, "please tune there".

Because the port is just a network connection, the radio can even sit on another computer or a Raspberry Pi in the shack.

Option 1: let On The Dial start rigctld

The simplest way if nothing else on your computer uses the radio yet.

  1. Open File → Settings → Radio.
  2. Tick Start Hamlib's rigctld when the program starts.
  3. Pick your radio from the Rig model list (over 300 entries, sorted by manufacturer).
  4. Choose the Device the radio is plugged into: /dev/ttyUSB0 on Linux, COM3 on Windows, /dev/cu.usbserial-… on macOS. The list shows what is currently plugged in.
  5. Set the Baud rate to what the radio's menu says, or leave "rig default".
  6. OK. The status bar should say Connected to rigctld and the big digits follow your tuning knob.

On Windows the download includes rigctld, nothing else to install. On Linux install the package libhamlib-utils (Debian, Ubuntu, Mint) or hamlib (Fedora, Arch, openSUSE) first. On macOS: brew install hamlib.

Option 2: another program already runs rigctld

If your logger or digital-mode program already controls the radio, do not start a second connection to the serial port; two programs cannot share one serial port. Let that program run rigctld and share it.

QLog

In Settings → Equipment → Rig edit your rig profile and tick Start rigctld daemon to share rig with other applications. QLog then launches rigctld on port 4532 (adjustable) and uses it itself. On The Dial with its default settings will find it right away.

WSJT-X and JTDX

These bundle Hamlib but only use it internally. Run rigctld yourself (option 3 below, or via On The Dial), then in WSJT-X choose Settings → Radio → Rig: Hamlib NET rigctl with network server localhost:4532. Now WSJT-X and On The Dial share the radio.

fldigi and flrig

fldigi can talk to rigctld directly: Configure → Rig Control → Hamlib, device localhost:4532, rig Hamlib NET rigctl. If you use flrig instead, start rigctld with model 4 (FLRig), which turns flrig into a rigctld source: rigctld -m 4.

CQRLOG

CQRLOG starts rigctld by itself (Preferences → TRX control). Enter the same port there and in On The Dial.

gqrx and SDR++ (software defined radios)

No Hamlib needed. gqrx has Tools → Remote control, which speaks the same protocol on port 7356: enable it and set On The Dial's port to 7356. SDR++ has the Rigctl Server module, default port 4532. Both accept the double-click tuning as well.

Anything else that offers "rigctld" or "rigctl server"

If a program can share the rig as rigctld, On The Dial can use it. Only the host and port matter.

Option 3: start rigctld by hand

Useful for testing, for a headless computer in the shack, or when you like terminals.

# list the radios Hamlib knows and their model numbers
rigctld -l

# Icom IC-7300 on the first USB serial port at 115200 baud
rigctld -m 3073 -r /dev/ttyUSB0 -s 115200

# Yaesu FT-991 on Windows, COM5
rigctld.exe -m 1035 -r COM5 -s 38400

# Kenwood TS-590SG on macOS
rigctld -m 2031 -r /dev/cu.usbserial-1420 -s 115200

# a radio with a LAN interface (Flex, Icom IC-705 over Wi-Fi, ...)
rigctld -m 2 -r 192.168.1.50:4532      # "NET rigctl": chain to another rigctld

# no radio at all, just to try the program
rigctld -m 1

Leave that window open. Then start On The Dial. To let another computer connect add -T 0.0.0.0 and use that computer's address in Settings → Radio → Host.

When it does not work

SymptomWhat to check
Status bar says Connection refusedrigctld is not running, or runs on another port. Start it (option 1 or 3) or check the port in the other program.
rigctld starts and exits at onceWrong device name, or the port is already in use by another program. On Linux also make sure your user may open serial ports: sudo usermod -aG dialout $USER, then log out and in.
Connected, but frequency stays at ---Wrong baud rate or CAT disabled in the radio's menu. Try rigctl -m <model> -r <device> -s <baud> f in a terminal until it prints a frequency.
Icom radios: rigctld complains about the CI-V addressAdd --civaddr=0x94 (the address from the radio's menu) to Extra arguments.
Frequency is right, station list is emptyNothing is scheduled within the ± range, or the databases have not been downloaded yet. See the status bar on the right.
Double-click does not tuneSome SDR programs only accept commands when their remote control allows it (gqrx: Remote control → Allow control).
